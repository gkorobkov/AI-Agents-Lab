# Проверка мобильной компоновки

## Различия, обнаруженные 10 ноября 2026 года

Пользователь предоставил реальный скриншот Chrome на Samsung Galaxy Fold 7 в сложенном состоянии. Он является свидетельством поведения телефона. Скриншоты настольного браузера с уменьшенным окном не заменяют проверку устройства.

В предыдущих проверках менялись главным образом ширина и высота viewport. Это проверяло адаптивные CSS-правила, но не подтверждало сенсорный режим. При повторной проверке agent-browser даже после `set device "Pixel 7"` сообщал Android User-Agent, но `matchMedia('(pointer: coarse)').matches` и `matchMedia('(hover: none)').matches` оставались `false`. Таким результатом нельзя подтверждать мобильную проверку.

Дополнительно команды agent-browser могут возвращать размеры к сохранённому профилю устройства: после установки высоты 780 через отдельный CDP-вызов следующая команда получала 915. Для этой задачи размеры, сенсорный ввод, проверки DOM и снимки выполнялись в одной последовательности CDP-команд без промежуточного сброса. `Emulation.setTouchEmulationEnabled` включён явно. До каждой проверки подтверждены фактические `innerWidth`, `innerHeight`, `devicePixelRatio`, `pointer: coarse`, `hover: none`.

## Причины видимых ошибок приложения

- В `app-navigation.css` режим отправки скрывался через `#workspace .composer-destination { display: none; }` на мобильных ширинах.
- `header #transport-toggle` получал почти всю строку через `flex-basis: calc(100% - 142px)`, что отодвигало шестерёнку от дропдауна.
- Блок URL принудительно переносился через `flex-basis: 100%` и `order: 2`.
- Общие действия были отдельными flex-элементами; теперь это одна группа справа. Навигация, транспорт, шестерёнка и URL сохраняют обычный порядок слева и переносятся по доступной ширине.

Сенсорными событиями проверены раскрытие дропдауна, выбор OpenAI API и открытие настроек шестерёнкой. Через клавиатуру проверена активация кнопки языка клавишей Enter. Проверка 412 × 480 является только приближением уменьшенной высоты, а не проверкой настоящей экранной клавиатуры.

Одной проверки переполнения документа недостаточно: дополнительно проверять ширину самого URL-input (не менее 100 CSS px), положение индикатора внутри поля и отсутствие пересечения поля с кнопкой истории. Шапка должна переноситься при нехватке места и выше 1000 px. Проверять значение readonly-поля URL над композером для Webhook и полного endpoint OpenAI.

## Что эмуляция не доказывает

Точная CSS-ширина и DPR телефона не определены по присланному изображению: оно могло быть уменьшено при отправке. Размеры 412 × 780 не следует называть измеренными параметрами Fold 7. На реальном телефоне дополнительно влияют масштаб страницы, системный размер шрифта, панели адреса и навигации Chrome, клавиатура, `visualViewport`, safe-area и положение прокрутки. Локальная и опубликованная версии, настройки localStorage, язык и выбранный транспорт также должны совпадать для сравнения.

Chrome с вертикальными вкладками забирает часть ширины окна под боковую панель и изменяет доступную высоту по сравнению с горизонтальными вкладками. Это может изменить CSS-переносы на ноутбуке. Следует измерять `innerWidth`/`innerHeight`, а не ширину всего окна или скриншота. Настройки пользовательского Chrome не воспроизводятся автоматически в отдельном тестовом профиле.

При наличии реального скриншота сравнивать отдельно шапку, строку отправки и видимую область контента. Не объявлять проверку на смартфоне выполненной по одной настольной эмуляции. Последующее подтверждение на Fold 7 остаётся отдельной проверкой пользователя или подключённого физического устройства.

Источники: [ограничения Device Mode](https://developer.chrome.com/docs/devtools/device-mode), [эмуляция Chrome DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/tot/Emulation/), [вертикальные вкладки Chrome](https://blog.google/products-and-platforms/products/chrome/new-chrome-productivity-features/).

## Повторная проверка после переноса управления чатом

Симптомы новых скриншотов воспроизведены подстановкой предыдущей версии `app-navigation.css` из Git при текущем HTML: иконка Tools выросла до 148.6 CSS px, группы навигации и действий получили `display: block`, поле endpoint стало белым. У актуального CSS иконка имеет ширину 14 CSS px. На сервере актуальный файл присутствовал, но HTML продолжал ссылаться на постоянный адрес `app-navigation.css?v=welcome-spacing`, допускавший повторное использование старой версии браузером.

`update-ui-assets.ps1`, вызываемый `ui-build.cmd`, теперь добавляет хеш содержимого к адресам локальных CSS и JavaScript главной страницы. Изменение файла меняет адрес ресурса даже при сборке `--no-increment`. Проверено совпадение всех 15 хешей и файлов в исходниках и `.build/ui/`.

Проверены Webhook и OpenAI API при 360×720, 400×740, 412×780, 640×780, 820×900, 900×700 и 1440×900. Размеры задавались через CDP с DPR 2.625 и явным включением touch; в каждом случае подтверждены реальные `innerWidth`, `innerHeight`, `pointer: coarse` и `hover: none`. Исправлены обрезание иконок заголовка при 360 px и лишний третий ряд строки OpenAI на узких ширинах. Переполнения документа и заголовка окна нет, кнопка отправки находится в пределах viewport. Сенсорными событиями проверены верхний дропдаун, смена режима с синхронизацией нижнего селектора и открытие настроек шестерёнкой.

Это эмуляция узкого и широкого экранов, а не измерение или проверка физического Fold 7. Панели Chrome, системный масштаб и экранная клавиатура телефона не воспроизведены.
