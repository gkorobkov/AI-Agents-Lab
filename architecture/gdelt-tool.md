# GDELT DOC 2.0: search_news_gdelt

Инструмент добавлен в существующий каталог `ui/tools-manifest.json`. Его можно проверить на странице Tools и подключить кнопкой «Подключить к агенту →». Профили и другие инструменты автоматически не переключаются. Новых сервисов и зависимостей нет: запрос выполняет браузер, провайдер должен разрешать CORS.

Определение функции и схема: `ui/tool-gdelt-news.json`. Общий адаптер для страницы Tools и вызовов из чата: `ui/tool-gdelt.js`. Настройки исполнения объявлены только в `CFG_GDELT_DEFAULTS` в начале `ui/index.html`. Отдельно открытая `tools.html` читает тот же блок, без собственных значений по умолчанию.

Официальный источник: [GDELT DOC 2.0](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/). GDELT ищет по английским переводам новостей. Предусмотрена нормализация популярных русских названий городов. Произвольный перевод остальных названий и тем не выполняется: используйте английский текст.

## Входной контракт

Имя функции: `search_news_gdelt`. Все поля необязательные по отдельности; обязательно хотя бы одно непустое `city` или `keywords`. Неизвестные поля отклоняются. `strict: false` сохраняет необязательные аргументы; фактический вызов проверяется адаптером.

| Поле | Тип и ограничения |
| --- | --- |
| `city` | Строка до 200 символов, город на русском или английском. Например, Москва → Moscow. |
| `keywords` | Строка до 200 символов, обычная поисковая фраза на английском. |
| `timespan` | По умолчанию `24h`. Положительное целое число и `min`, `h`, `d`, `w`, `m`. Минимум 15 минут, максимум доступное окно в 3 календарных месяца. |
| `start_date` | UTC ISO 8601: `YYYY-MM-DDTHH:mm:ss[.SSS]Z`. |
| `end_date` | Такой же формат. Даты должны быть в доступном окне, не в будущем, интервал — минимум 15 минут. |
| `source_language` | Название языка на английском или трёхбуквенный код GDELT. Есть алиасы русский/russian/ru и английский/english/en. |
| `source_country` | Страна **издателя**, английское название или двухбуквенный код **FIPS**, не ISO. Есть алиасы Россия, США, Великобритания. |
| `sort` | `datedesc` (по умолчанию) или `hybridrel`. |
| `limit` | Целое 1–50, по умолчанию 10. |

Абсолютные даты заменяют `timespan`, даже если он передан. При одном `start_date` конец — текущее UTC-время. При одном `end_date` начало — граница доступного окна. Оба значения передаются как `startdatetime`/`enddatetime` в формате `YYYYMMDDHHMMSS`.

Обычные текстовые поля не принимают операторы GDELT: кавычки, скобки, двоеточия, логические операторы и исключения. Город и тема формируются как точные фразы. Фильтры языка и страны добавляются внутри `query`, а не как отдельные HTTP-параметры. Запрос: GET на настроенный публичный endpoint, `mode=artlist`, `format=json`, без авторизации.

## Выходной контракт

```text
{
  source: "gdelt",
  status: "ok" | "empty" | "error",
  query: { city?, keywords?, timespan? | (start_date, end_date),
           source_language?, source_country?, sort, limit },
  count: integer,
  articles: [{ title: string|null, url: string, published_at: string|null,
               domain: string|null, language: string|null,
               source_country: string|null, image_url: string|null }],
  error?: { category: string, message: string },
  meta: { tool_name: string, request_id: string, duration_ms: integer,
          external_http_status: integer|null, result_count: integer,
          error_category: string|null }
}
```

`query` содержит нормализованные значения и применённые значения по умолчанию. При ошибке валидации — пустой объект. `error` присутствует только для `status=error`; `count=0`, `articles=[]`. Категории: `invalid_parameters`, `http`, `rate_limit`, `invalid_response`, `invalid_json`, `timeout`, `unavailable`, `cancelled`. Текст ошибок не содержит stack trace и сырого ответа сервера.

`published_at` — нормализованное поле `seendate`: время обнаружения/регистрации публикации GDELT, **не дата мероприятия**. Отсутствующая или некорректная дата становится `null`; записи с будущей датой исключаются. Инструмент не добавляет описания статей, расписания, билеты или сведения о наличии мест. Агенту переданы инструкции ссылаться на статьи и сообщать об отсутствии данных или ошибке.

Ссылки разрешены только HTTP(S), без встроенных credentials. Для удаления дублей нормализуются регистр домена, fragment, порядок query-параметров; удаляются `utm_*`, `fbclid`, `gclid`. Отсутствующие необязательные поля становятся `null`.

Для временных сетевых ошибок, timeout, HTTP 429 и 5xx выполняется не более одной повторной попытки. Между попытками — 5,5 с. У каждой попытки timeout 45 с; общий 30-секундный таймер HTTP-инструментов на GDELT не распространяется. Запросы сериализуются через Web Locks для чата, Tools и других вкладок этого origin; после каждого ответа выдерживается пауза 5,5 с. Без Web Locks действует очередь внутри страницы и общий timestamp в localStorage. Заголовок Retry-After учитывается без уменьшения: если сервер требует ждать более 60 с, автоматический повтор не выполняется. Интерфейс показывает очередь, ожидание ответа и повтор. Ошибки параметров, HTTP 4xx кроме 429, текст/HTML с HTTP 200, некорректный JSON и неверная структура ответа не повторяются. Отмена прекращает ожидание и запрос.

Наблюдаемость: объект `meta` также отправляется как `CustomEvent('tool:request', {detail: meta})`. Если Network показывает HTTP 429, а `external_http_status=null`, браузер мог заблокировать доступ к ответу из-за отсутствия CORS-заголовков. JavaScript не может восстановить этот статус; интерфейс пишет «HTTP-статус недоступен браузеру» и показывает категорию/причину. Очередь ограничивает запросы только этого приложения, но не других клиентов с тем же внешним IP. При повторной диагностике 11 ноября 2026 года запрос `Moscow festival` получил HTTP 429 за 10,3 с; заголовок Access-Control-Allow-Origin отсутствовал. В браузере проверено: параллельные вызовы из чата и iframe Tools сериализуются через Web Locks, интервал между запросами — 5507 мс.

Событие не содержит поисковой фразы, тела ответа или секретов; внешняя система хранения логов не добавляется.

## Пример

Вызов:

```json
{"city":"Москва","keywords":"festival","timespan":"7d","limit":1}
```

Иллюстративный ответ, не реальные данные API (идентификатор и время исполнения изменяются):

```json
{
  "source":"gdelt",
  "status":"ok",
  "query":{"city":"Moscow","keywords":"festival","sort":"datedesc","limit":1,"timespan":"7d"},
  "count":1,
  "articles":[{"title":"Example title","url":"https://example.com/article","published_at":"2026-11-10T12:00:00Z","domain":"example.com","language":"English","source_country":"Russia","image_url":null}],
  "meta":{"tool_name":"search_news_gdelt","request_id":"example-request-id","duration_ms":123,"external_http_status":200,"result_count":1,"error_category":null}
}
```

## Запуск и проверка

1. Запустить `ui-start.cmd`, открыть `http://localhost:8080/?page=tools` и принять соглашение.
2. Выбрать GDELT. Пример запроса и JSON-ответа находится в сворачиваемом разделе описания. Изменить значения аргументов в существующем разделе проверки через LLM; они используются и для HTTP-проверки. Пустые необязательные значения пропускаются.
3. Нажать «Выполнить HTTP-запрос к Tool». Проверить нормализованный ответ и `meta`. При частых запросах возможен HTTP 429.
4. Нажать «Подключить к агенту →», настроить LLM и использовать запрос «Что произошло сегодня в Москве?». Ручной и автоматический режимы используют существующий механизм Function Calling. Кнопка проверки через LLM требует собственных настроек провайдера.
5. Автоматические проверки без внешней сети: `node --test tests/gdelt.test.cjs`.

Проверено 11 ноября 2026 года:

- 14 автоматических тестов GDELT проходят (добавлены сериализация, cooldown, отмена в очереди, Retry-After и скрытые браузером ответы): варианты поиска, фильтры, даты, лимиты, безопасные ссылки, дубликаты, пустые ответы, HTTP/JSON/timeout/cancel/retry, регистрация и передача аргументов Function Calling, изоляция обычного HTTP-инструмента.
- Браузер: принят consent; 1440×900, 640×780, 400×740, без горизонтального переполнения, раскрыт пример JSON. На узких экранах DPR 2.625, `pointer: coarse`, `hover: none`; проверены сенсорное нажатие и клавиатурная активация. Это эмуляция, без физического телефона.
- Существующая HTTP-кнопка проверена с фиктивным ответом; подключение к агенту сохраняет адаптер, определение функции включается в запрос LLM. Полный обработчик полученного `tool_calls` также проверен на фиктивном ответе: результат GDELT попадает в продолжение диалога как `role=tool` с исходным `tool_call_id`.
- Живой API: запрос Москвы из Node.js получил HTTP 200 `application/json` и статью; браузерный вызов адаптера вернул `ok`, `count=1`, HTTP 200. Отдельные запросы также получили HTTP 429 с указанием интервала не менее 5 секунд.
- Дополнительный живой браузерный запрос по теме `AI` завершился сетевой ошибкой без HTTP-статуса (`unavailable`); этот сценарий поиска подтверждён фиктивными ответами, его успешность на живом API не подтверждена.
- Старый набор `tests/mcp.test.cjs` имеет 10 ошибок `MaterialCatalog is not defined` в исходном окружении теста. Его файлы и MCP-модули совпадают с HEAD; это существующая проблема, не исправлявшаяся в рамках GDELT.

Изменения подготовлены локально; публикация и вызов платного LLM-провайдера не выполнялись.
