# Формат инструмента библиотеки Tools

Схема полей JSON-записи версии 1: типы, допустимые значения и правила заполнения.

## Структура

```text
record
├── schemaVersion, id, title
├── docsUrl, providerUrl, apiKeyUrl, apiKeyInstructions
├── tool
│   ├── name, description, parameters, strict
│   ├── adapter
│   └── http
│       ├── url, alternativeUrl, useAlternativeUrl, method
│       ├── mappings[]: key, value, testValue, omitIfEmpty
│       ├── body
│       └── auth: placement, name, prefix, secretId
└── exampleRequest, exampleResponse
```

JSON не поддерживает комментарии, одинарные кавычки и запятые после последнего элемента. `true` и `false` вне строк пишутся без кавычек.

## Поля записи

| Поле | Тип и назначение | Как править |
| --- | --- | --- |
| `schemaVersion` | Число, обязательно `1`. | Не менять при редактировании инструмента. |
| `id` | Обязательная строка, 1–100 латинских букв, цифр, `_` или `-`. Уникальный идентификатор записи. | Сохранить при обновлении существующего файла. Для нового инструмента задать новый ID. |
| `title` | Обязательная непустая строка до 120 символов. Название в библиотеке. | Можно использовать русский текст и пробелы. |
| `docsUrl` | Строка, ссылка на документацию API. | Указать страницу документации провайдера. |
| `providerUrl` | Строка, сайт провайдера. | Указать сайт сервиса. |
| `apiKeyUrl` | Строка, ссылка на получение ключа. | Указать кабинет или инструкцию. |
| `apiKeyInstructions` | Строка, инструкция пользователю по получению ключа. | Описать шаги; сам ключ сюда не вставлять. |
| `tool` | Обязательный объект конфигурации функции и HTTP. | См. ниже. |
| `exampleRequest` | Объект аргументов функции. Пример и начальные данные ручного теста. | Использовать имена из `parameters.properties` и соответствующие типы. |
| `exampleResponse` | Иллюстрация ответа API, любое JSON-значение. | Не влияет на реальный ответ. Можно убрать вместе с полем. |
| `builtin` | Служебный флаг, добавляется приложением. | В исходном файле не нужен. Встроенный инструмент редактируют через копию или исходный JSON. |

Ссылки, инструкция и примеры необязательны. Они не передаются модели как параметры функции.

## Описание функции `tool`

| Поле | Тип и назначение | Как править |
| --- | --- | --- |
| `name` | Обязательная строка, 1–64 латинских букв, цифр, `_` или `-`. Имя функции для LLM. | Использовать понятное уникальное имя, например `lookup_record`. |
| `description` | Обязательная непустая строка. Объясняет модели назначение функции, когда её вызывать, какие сведения уточнять и как понимать ответ. | Переносы записывать как `\n`. Согласовать описание с аргументами и HTTP-запросом. |
| `parameters` | Обязательная **строка**, содержащая JSON Schema аргументов. Это JSON внутри JSON. | Не заменять строку объектом. Для правки распаковать строку через `JSON.parse`, изменить схему и сериализовать через `JSON.stringify`. |
| `strict` | Булево. Запрашивает строгий формат аргументов у поддерживающей его модели. | Для строгой схемы перечислить все свойства в `required` и задать `additionalProperties: false`. Необязательное значение при необходимости моделировать допустимым типом `null`; проверьте поддержку конкретной моделью. |
| `adapter` | Необязательная строка. Значение `gdelt` включает отдельный сборщик запроса. | Для обычного HTTP-инструмента поле убрать. Произвольные значения не создают новые адаптеры. |
| `http` | Обязательный объект настройки вызова. | См. следующую таблицу. |

Внутри распакованного `parameters`:

| Поле | Значение |
| --- | --- |
| `type` | Для корня обязательно `"object"`. |
| `properties` | Объект: ключ — имя аргумента, значение — объект его JSON Schema. Даже при отсутствии аргументов нужен `{}`. |
| `properties.<имя>.type` | Тип аргумента: `string`, `boolean`, `number`, `integer`, `object`, `array`, `null` или массив допустимых типов. |
| `properties.<имя>.description` | Объяснение аргумента для модели, формат и ограничения. |
| `properties.<имя>.enum` | Массив допустимых значений, если нужен фиксированный выбор. |
| `properties.<имя>.minimum`, `maximum` | Нижняя и верхняя границы числа. |
| `properties.<имя>.properties`, `required`, `additionalProperties` | Описание вложенного объекта. |
| `properties.<имя>.items` | Схема элементов массива. |
| `required` | Массив имён обязательных аргументов; все имена должны существовать в `properties`. |
| `additionalProperties` | Обычно `false`: запрещает лишние аргументы в схеме для LLM. |

Схема передаётся модели. Локальный HTTP-сборщик проверяет обязательные аргументы, верхнеуровневые типы, `enum`, `minimum` и `maximum`; он не является полным валидатором JSON Schema. Вложенные ограничения, `format`, `pattern` и прочие ключевые слова нельзя считать локально проверенными. `default` в схеме не подставляет отсутствующие аргументы автоматически. Изменять настраиваемые значения приложения следует только в блоке `CONFIGURABLE DEFAULTS` в `ui/index.html`; значения записи инструмента описывают конкретный API и его примеры.

## HTTP и авторизация

| Поле `tool.http` | Тип и поведение | Как править |
| --- | --- | --- |
| `url` | Строка, основной абсолютный HTTP(S) URL без встроенного логина и пароля. | Указать endpoint. Поддерживает шаблоны `{{имя}}`. |
| `alternativeUrl` | Строка, альтернативный URL, в том числе относительный к странице. | Оставить `""`, если альтернативы нет. |
| `useAlternativeUrl` | Булево, выбор альтернативного адреса. | `false` для основного. При `true` нужен непустой `alternativeUrl`. Сохранённый выбор в браузере может перекрыть значение встроенного инструмента. |
| `method` | `"GET"` или `"POST"`. | GET отправляет mappings в query; POST — в JSON-тело. |
| `mappings` | Массив HTTP-параметров. Можно `[]`. | Каждый элемент обязан иметь строковые `key` и `value`. |
| `mappings[].key` | Имя параметра HTTP, уникальное внутри массива. | Может отличаться от имени аргумента LLM. Запрещены `__proto__`, `prototype`, `constructor`. |
| `mappings[].value` | **Обязательная строка**: шаблон либо константа. | `"{{имя}}"` подставляет значение аргумента; `"5"` всегда задаёт константу. Не удалять при добавлении `testValue`. |
| `mappings[].testValue` | Необязательное тестовое значение; рекомендуется строка. | Подставляет начальное значение поля ручной проверки. Для boolean использовать `"true"`/`"false"`, для числа — `"5"`. Не задаёт значение реального вызова LLM. |
| `mappings[].omitIfEmpty` | Необязательное булево. | При `true` параметр пропускается, если подстановка дала `""`, `null` или `undefined`. `false` и `0` сохраняются. Отсутствующий аргумент в шаблоне всё равно вызывает ошибку. |
| `body` | Строка с JSON-шаблоном тела POST. | `""`: тело собирается из mappings. Непустое тело должно быть валидным JSON; подстановки в нём задаются строками, например `{"city":"{{city}}"}` внутри сериализованной строки. Для GET не используется. |
| `auth` | Необязательный объект авторизации. | При отсутствии ключ не добавляется. |
| `auth.placement` | `"none"`, `"header"` или `"query"`. | `"none"` — без ключа, `"header"` — ключ в заголовке, `"query"` — ключ в URL. |
| `auth.name` | Имя заголовка или query-параметра ключа. | Например `"X-Access-Token"` или `"Authorization"`. Обязательно при активной авторизации. |
| `auth.prefix` | Строка перед ключом. | `""` — без префикса. `"Bearer "` — префикс с пробелом, если его требует API. |
| `auth.secretId` | Строка, идентификатор слота ключа. | Например `"service_api_key"`. Это имя слота, а не секрет. Обязательно при активной авторизации. |

Точный шаблон `{{имя}}` сохраняет тип аргумента: boolean остаётся boolean при формировании JSON-тела. Вставка в строку, например `city={{city}}`, превращает значение в текст. Поддерживается путь `{{location.city}}`. В URL подстановки кодируются, GET-параметры кодирует `URLSearchParams`. Реальный ключ вводят в интерфейсе: он хранится в `sessionStorage` вкладки с привязкой к origin сервера и не должен попадать в JSON инструмента.

## Правила заполнения значений

- Подстановка аргумента: `value: "{{имя}}"`. Имя должно существовать в `parameters.properties`; обязательные аргументы перечисляются в `required`.
- Постоянное HTTP-значение: `value: "текст"`, `value: "5"` или `value: "false"`. Поле `value` всегда имеет строковый тип, даже для чисел и булевых значений.
- Пустое значение: `value: ""`. Для исключения пустого параметра из запроса задать `omitIfEmpty: true`.
- Тестовое значение: `testValue` заполняет поле ручной проверки и не заменяет `value`. При начальном заполнении оно имеет приоритет над соответствующим значением `exampleRequest`; значения, сохранённые в текущей странице, имеют приоритет над обоими.
- При замене шаблона константой убрать аргумент из `parameters.properties`, `required` и `exampleRequest`, если на него больше не ссылаются другие шаблоны. Удалить устаревшее `testValue`, если оно перекрывает нужное отображаемое значение.
- Имена в `required` и `exampleRequest` должны согласовываться с `parameters.properties`, а типы значений примера — с типами аргументов.
