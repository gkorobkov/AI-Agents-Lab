# Подключаемые лабораторные

Каждая лабораторная — отдельный JSON-файл без исполняемого кода. Общий интерфейс `ui/labs.html` загружает определения, показывает ссылки в полосе «Лабы», создаёт формы и ведёт прогресс.

## Добавление на сайт

1. Создайте файл в `ui/`, например `lab-context.json`, по образцу `Labs/example-lab.json` или `ui/lab-chat-completions.json`.
2. Добавьте имя файла в массив `labs` файла `ui/labs-manifest.json`. Порядок массива задаёт порядок ссылок.
3. Откройте сайт через локальный HTTP-сервер (`ui-start.cmd`). Перезагрузите страницу.

Пример каталога:

```json
{"schemaVersion": 1, "labs": ["lab-chat-completions.json", "lab-context.json"]}
```

Файлы лежат непосредственно в `ui/`, поэтому существующий `ui-build.cmd` включает их вместе с JS и CSS. Запуск `ui-build.cmd --no-increment` проверяет сборку без изменения версии. Публикация выполняется отдельно существующим процессом деплоя.

Для локального подключения используйте «Лабы → Загрузить JSON». Такая лаба сохраняется только в текущем браузере и доступна после перезагрузки. Каталог сайта имеет приоритет при совпадении id. Импорт с тем же id и другим содержимым отклоняется, чтобы не подменять условия текущей работы. Для отдельной работы используйте новый id.

Ссылка на встроенную работу: `index.html?page=labs&lab=chat-completions`. Отдельная страница: `labs.html?lab=chat-completions`. Ссылки на старые эксперименты, например `labs.html#lab4`, сохранены.

## Формат определения (schemaVersion: 1)

- `id`: уникальный идентификатор, латинские строчные буквы, цифры и дефисы; начинается с буквы или цифры, до 64 символов.
- `version`: версия содержания, до 32 символов; строчные буквы, цифры, точки и дефисы.
- `title`, `description`: название (до 200 символов) и описание (до 3000).
- `introduction`, `preparation`, `reportInstructions`: необязательные массивы блоков.
- `experiments`: от 1 до 100 объектов `{ "id", "title", "blocks" }`. Id заданий уникальны в пределах лабы; `prepare`, `experiments`, `report` зарезервированы.

Блоки:

| type | Поля | Отображение |
| --- | --- | --- |
| `paragraph` | `text`, необязательный `tone`: `normal`, `muted`, `question` | Абзац / наблюдение / вопрос |
| `list` | `items`: массив строк, `ordered`: boolean | Нумерованный или маркированный список |
| `code` | `text`, необязательный `label` | Сохраняющий форматирование пример с кнопкой копирования |
| `details` | `title`, `blocks` | Раскрываемое пояснение |

Строки отображаются как текст: HTML и скрипты не исполняются. Максимум 100 блоков в массиве, вложенность до 4 уровней, размер определения до 2 МБ. Не вставляйте секреты в учебные материалы.

При изменении условий опубликованной работы увеличивайте `version`. Отчёты разделены по `id` и `version`, поэтому ответы предыдущей версии не приписываются новым заданиям. Для просмотра прежних отчётов нужен JSON старой версии на отдельной странице/в браузере без конфликтующего определения.

## Прогресс и отчёты

У каждого эксперимента есть результат, запросы/ответы/параметры и вывод. Статусы: «Не начато», «В работе», «Выполнено», «Недоступно». Начало ввода переводит задание в работу. Для «Выполнено» нужны результат и вывод; для «Недоступно» — причина в результате. Недоступные задания не считаются выполненными. Изменение обязательного ответа на пустой снимает отметку выполнения.

Автор, группа, ответы и общий вывод автоматически сохраняются в `localStorage` под ключом `ai_lab_report_v1:<id>:<version>`. Локальные определения — `ai_lab_definitions_v1`. Ошибка сохранения показывается явно; экспорт остаётся доступным. Удаление данных сайта удаляет локальные работы.

- **Отчёт .md**: читаемый Markdown с условиями, статусами, результатами и выводами для проверки.
- **Отчёт .json**: переносимый отчёт, включая снимок определения лабы, автора, ответы и дату экспорта. Можно восстановить через «Загрузить JSON» (до 32 МБ). Перед заменой ответов запрашивается подтверждение.

Можно экспортировать незавершённую работу; её реальные статусы останутся в отчёте. Экспорт не читает ключи API, настройки подключения или историю чата. Вставленные вручную данные включаются как есть — проверяйте их перед отправкой. Автоматической отправки преподавателю и серверного хранения нет. Поля отчёта помечены `ym-hide-content` / `ym-disable-keys`.
