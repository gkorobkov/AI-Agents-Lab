OpenAI API · Chat Completions

Как устроен запрос к LLM моделиHow a request to the LLM model works

API — интерфейс, через который приложение обращается к LLM модели. Этот чат отправляет JSON на POST /chat/completions: model выбирает LLM модель, а messages[] содержит инструкции и реплики. OpenAI-совместимый сервер использует похожий формат, но набор поддерживаемых параметров может отличаться.

temperature и top_p регулируют выбор следующего токена; меняйте один из них за раз. max_completion_tokens ограничивает ответ, n запрашивает варианты. Доступные значения и ограничения зависят от LLM модели; кнопки «?» у полей показывают справку и границы этой формы.

tools описывает функции. LLM Модель возвращает имя и аргументы; приложение выполняет действие или вы вводите результат вручную. Затем результат отправляется LLM модели для продолжения. Сворачивание карточки скрывает только редактор и не удаляет функцию из запроса.

Перед отправкой проверьте предпросмотр JSON. После ответа сравните choices, finish_reason и usage в полном ответе провайдера.

The API lets an app communicate with a model. This chat posts JSON to /chat/completions: model selects the model and messages[] carries instructions and conversation turns. Compatible providers can support different subsets of parameters.

temperature and top_p affect token selection; adjust one at a time. max_completion_tokens limits output and n requests alternatives. The question marks beside fields explain the form limits and effects.

tools defines functions. The model requests a function and arguments; the app executes it or you enter its result, then send that result back for continuation. Collapsing a function hides its editor without removing it from the request.

Inspect the JSON preview before sending, then compare choices, finish_reason and usage in the provider response.

Как работать с MCP: от первого вызова до ответа агента

MCP — общий язык общения приложения с инструментами. Один сервер предоставляет набор функций. Сначала приложение узнаёт, какие функции доступны и какие данные им нужны, затем вызывает выбранную функцию. Здесь вы можете проверить весь путь вручную и подключить инструменты к чату.

Маршрут в чате: пользователь → приложение → LLM предлагает вызов → MCP-клиент приложения → MCP-сервер → инструмент → результат в приложении → LLM → ответ пользователю.

1. Кто участвует и куда идут запросы
  • Пользователь пишет задачу в чате или вручную выбирает инструмент и вводит аргументы в библиотеке.
  • Приложение AI Agents Lab отправляет запросы модели, показывает вызовы и результаты. Его MCP-клиент — часть кода, которая общается с MCP-сервером.
  • LLM модель получает имя, описание и схему аргументов функции. Она может предложить вызов: имя функции и значения аргументов. Само действие выполняет приложение через MCP-клиент.
  • MCP-сервер сообщает список инструментов и принимает команды на их выполнение. Обработчик функции возвращает подготовленный ответ или обращается к внешнему API.
  • Внешний API, если нужен инструменту, получает обычный HTTP-запрос — например, название города для поиска координат. Ответ возвращается обработчику, затем MCP-клиенту.

Здесь есть два отдельных обмена: приложение ↔ API модели и MCP-клиент ↔ MCP-сервер. В этой лаборатории модель напрямую к адресу MCP не подключается. При ручной проверке в библиотеке LLM не участвует.

2. Первый эксперимент без LLM: приветствие пользователя
  1. В списке слева выберите «Учебный помощник». В нём есть функция greet_student.
  2. В разделе 03 нажмите «Получить инструменты». Клиент знакомится с сервером и получает список функций. В поле «Инструмент» появится greet_student. Приветствие на этом шаге ещё не выполняется.
  3. Выберите функцию. В «Аргументы · JSON» введите {"name":"Анна"}. Это конкретное значение. Схема лишь описывает правило: поле name обязательно и должно быть строкой.
  4. Нажмите «Вызвать инструмент». Клиент отправит tools/call с именем функции и аргументами. Обработчик подставит «Анна» вместо {{name}} в шаблоне.
  5. В «Результат tools/call» найдите приветствие и следующий шаг. В карточках обмена раскройте запрос и ответ. Все сообщения также доступны в «Полный журнал сообщений · JSON».
  6. Замените имя на «Иван» и повторите вызов. Приветствие изменится. Попробуйте {}: обязательное имя отсутствует, поэтому ожидается ошибка проверки аргументов.

Путь: кнопка в браузере → MCP-клиент → учебный обработчик в том же браузере → результат на странице. Для этого шаблона не нужны сеть или модель.

Аргументы:
{"name":"Анна"}

Данные ответа внутри MCP-результата:
{
  "message": "Привет, Анна!",
  "next_step": "Откройте Лабы и начните первый эксперимент."
}

Полный MCP-ответ содержит оболочку протокола. Сравните эти данные с результатом и журналом на странице.

3. Что означают initialize, tools/list и tools/call

В журнале видны сообщения JSON-RPC: у запроса есть метод, параметры и идентификатор id. Ответ с тем же id относится к этому запросу. У уведомления ответа нет. В лаборатории реализована такая последовательность:

  1. initialize — клиент и сервер обмениваются сведениями о себе, возможностях и согласуют поддерживаемую версию протокола.
  2. notifications/initialized — клиент уведомляет сервер, что готов к работе.
  3. tools/list — клиент запрашивает каталог. Сервер возвращает имена, описания и inputSchema — правила для входных данных. Получение каталога не запускает функции.
  4. tools/call — клиент просит выполнить одну функцию с конкретными аргументами. Сервер возвращает результат или ошибку.
{
  "jsonrpc": "2.0",
  "id": 4,
  "method": "tools/call",
  "params": {
    "name": "greet_student",
    "arguments": {"name": "Анна"}
  }
}

Число id — пример. Реальные сообщения смотрите в журнале обмена после проверки и вызова.

4. Подключение к агенту: как результат доходит до модели
  1. Откройте библиотеку внутри AI Agents Lab через пункт MCP. Проверьте пример и нажмите «Подключить к агенту →». Приложение сохранит копию определения, добавит функции в настройки OpenAI API и включит Tools.
  2. Настройте доступного провайдера и модель с поддержкой tools. Проверьте, что в Tools появилась функция MCP. Её имя будет начинаться с mcp_: приложение различает функции разных серверов.
  3. В чате напишите: «Вызови инструмент приветствия пользователя для Анны и передай мне результат». Приложение отправит модели задачу и определения подключённых функций.
  4. Если модель выберет инструмент, она вернёт tool_calls: имя функции и аргументы, например {"name":"Анна"}. Это предложение выполнить действие; результата инструмента ещё нет. Наличие Tools само по себе не гарантирует вызов.
  5. В карточке вызова проверьте аргументы и нажмите «Выполнить MCP-вызов». Приложение найдёт подключённый сервер и отправит ему tools/call с исходным именем greet_student.
  6. Сервер выполнит функцию. MCP-клиент получит ответ и заполнит поле результата в чате. Теперь данные есть у приложения, но ещё не отправлены модели.
  7. Нажмите «Продолжить с tool results». Приложение отправит данные в API модели сообщением роли tool, связанным с нужным вызовом. Если вызовов несколько, сначала заполните результат каждого.
  8. Модель прочитает результат и ответит пользователю либо запросит следующий инструмент. Для следующего вызова последовательность повторяется.

Два действия: «Выполнить MCP-вызов» получает данные от инструмента; «Продолжить с tool results» передаёт их модели для продолжения ответа.

Агент получает отдельную копию MCP. После изменения библиотеки удалите старую копию из настроек агента и подключите обновлённую.

5. Наглядный пример с HTTP API: координаты города
  1. Нажмите «+ Собрать свой MCP». В разделе 02 выберите Open-Meteo · Geocoding из библиотеки Tools и нажмите «Добавить HTTP-инструмент».
  2. Нажмите «Получить инструменты», выберите добавленную функцию и передайте {"name":"Москва"}. Нажмите «Вызвать инструмент».
  3. Обработчик подставит город в параметры HTTP-запроса к API геокодирования. В результате ищите найденные города, широту и долготу. Если совпадений несколько, сравните страну и другие данные.
  4. Подключите MCP к агенту и попросите: «Найди координаты Москвы с помощью инструмента геокодирования». Выполните предложенный MCP-вызов и передайте результат модели кнопкой продолжения.

В учебном стенде: браузер → локальный MCP-обработчик → HTTP API Open-Meteo → обработчик → браузер. Обмен MCP локальный, но запрос к API настоящий. API должен разрешать запросы из браузера (CORS).

На отдельном сервере: браузер → адрес MCP-сервера → обработчик на сервере → HTTP API → MCP-сервер → браузер. Внешний API вызывает сервер. Браузеру требуется разрешение CORS от MCP-сервера.

Настройки HTTP-инструмента копируются из Tools при добавлении. Чтобы изменить URL или параметры, отредактируйте инструмент в Tools и добавьте обновлённую копию в MCP.

6. Где находится сервер: сохранение, JSON и запуск Node.js
  • Учебный стенд выполняет обмен MCP и обработчики в браузере. Для шаблонного приветствия не нужны Node.js или URL.
  • «Сохранить копию» сохраняет определение в библиотеке этого браузера. «Скачать JSON» переносит настройки для импорта. Эти действия не запускают и не публикуют сервер.
  • «Скачать server.mjs» в разделе 04 создаёт программу из конструктора. Выполните приведённые там команды в папке с файлом. Пока процесс Node.js запущен, он принимает запросы по адресу http://127.0.0.1:3100/mcp. Адрес 127.0.0.1 означает компьютер, на котором работает браузер.
  • Нажмите «Подключить сервер», введите этот адрес и нажмите «Получить инструменты». Сообщения пойдут по HTTP к отдельному процессу. Совместимый внешний MCP-сервер подключается по его адресу.
  • Если MCP-сервер защищён, укажите выданный владельцем Bearer token. Это доступ к MCP-серверу; ключ внешнего API относится к HTTP-инструменту и настраивается отдельно.

Библиотека поддерживает инструменты через учебный стенд и Streamable HTTP. Другие возможности MCP, например resources и prompts, здесь не реализованы. Подробнее: официальная спецификация MCP.

7. Если вызов не получился: где искать причину
  • Нет списка функций: нажмите «Получить инструменты». После изменения настроек получите список заново.
  • Ошибка JSON или аргументов: используйте двойные кавычки, проверьте имена полей, типы и обязательные значения по схеме функции.
  • Нет подключения: проверьте URL, запущен ли сервер, нужен ли токен и разрешён ли CORS. Для локального сервера браузер может запросить доступ к локальной сети.
  • Ошибка в результате инструмента: соединение могло сработать, но обработчик или внешний API не выполнили задачу. Прочитайте результат и журнал обмена; исправьте причину перед повторным вызовом.
  • Модель отвечает без инструмента: проверьте его подключение в Tools, поддержку tools у модели и формулировку задачи. Сначала убедитесь, что ручной вызов в библиотеке работает.
  • Результат есть, ответа модели нет: проверьте, нажали ли «Продолжить с tool results» и заполнены ли результаты всех вызовов.
