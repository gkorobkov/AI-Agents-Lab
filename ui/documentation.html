AI Agents Lab · Лаборатория ИИ Агентов

ИИ Агенты: обучение и эксперименты в браузере

AI Агенты — это помощники на основе языковых моделей, которые используют инструкции, контекст диалога и внешние инструменты для решения задач. В AI Agents Lab можно изучать поведение AI Агентов: менять настройки модели, смотреть полный запрос и ответ сервера, подключать функции и проверять результаты их вызова.

Лаборатория ИИ Агентов объединяет чат с моделями, лабораторные работы и библиотеку Tools / function calling. OpenAI API — одно из направлений практики: параметры генерации, системные инструкции, история сообщений и JSON Schema. Для сценариев автоматизации доступно подключение через n8n webhook.

В библиотеке можно настроить HTTP-запрос, сопоставить аргументы функции с параметрами URL и проверить ответ сервиса. Первый готовый инструмент — поиск координат городов через Open-Meteo Geocoding. Модель получает описание функции и схему аргументов; приложение выполняет HTTP-вызов и позволяет передать результат обратно модели.

OpenAI API · Chat Completions

Как устроен запрос к моделиHow a model request works

API — интерфейс, через который приложение обращается к модели. Этот чат отправляет JSON на POST /chat/completions: model выбирает модель, а messages[] содержит инструкции и реплики. OpenAI-совместимый сервер использует похожий формат, но набор поддерживаемых параметров может отличаться.

temperature и top_p регулируют выбор следующего токена; меняйте один из них за раз. max_completion_tokens ограничивает ответ, n запрашивает варианты. Доступные значения и ограничения зависят от модели; кнопки «?» у полей показывают справку и границы этой формы.

tools описывает функции. Модель возвращает имя и аргументы; приложение выполняет действие или вы вводите результат вручную. Затем результат отправляется модели для продолжения. Сворачивание карточки скрывает только редактор и не удаляет функцию из запроса.

Перед отправкой проверьте предпросмотр JSON. После ответа сравните choices, finish_reason и usage в полном ответе провайдера.

The API lets an app communicate with a model. This chat posts JSON to /chat/completions: model selects the model and messages[] carries instructions and conversation turns. Compatible providers can support different subsets of parameters.

temperature and top_p affect token selection; adjust one at a time. max_completion_tokens limits output and n requests alternatives. The question marks beside fields explain the form limits and effects.

tools defines functions. The model requests a function and arguments; the app executes it or you enter its result, then send that result back for continuation. Collapsing a function hides its editor without removing it from the request.

Inspect the JSON preview before sending, then compare choices, finish_reason and usage in the provider response.

Концепт переключателя в UI

В бургер-меню появится раздел «Режим подключения» с тремя карточками, а в десктопной шапке — компактный индикатор активного режима. После выбора видны только нужные поля: webhook URL; либо API URL, ключ и модель; либо URL Python-бэкенда. Поле сообщения и формат ответа не меняются.

HTTP · JSON

Что именно отправляет текущий UI

message — ваш текст. sessionId — метка разговора: по ней workflow понимает, какие сообщения относятся к одному диалогу.

POST · Content-Type: application/json
{ "message": "Привет!", "sessionId": "session_abc123" }
GET · QUERY PARAMETERS
?sessionId=session_abc123&message=Привет%21

Какой ответ принимает чат

RECOMMENDED SUCCESS
{
  "message": "Готово!",
  "suggestions": ["Дальше"],
  "debug": { "node": "Agent" }
}

Вместо message допустимы алиасы text или output. suggestions и debug необязательны.

ERROR
{ "error": "Не удалось вызвать модель" }

Любой непустой JSON чат может показать как есть, но единый формат с message проще поддерживать.

Пошаговая настройка

Как подключить каждый режим

Работает сейчас

n8n webhook

Создайте Webhook → обработайте message/sessionId → завершите Respond to Webhook объектом {message: "…"} → вставьте URL в чат. Test URL работает, пока workflow слушает тест; Production — после активации workflow.

Планируется

Direct LLM API

Укажите Base URL, модель qwen3.6-unlim и API key. Провайдер должен разрешать CORS. Подходит для локального обучения: секрет виден браузеру и не подходит для публичного приложения.

Планируется

Python backend

Создайте endpoint с тем же контрактом message/sessionId, храните ключ NeuralDeep в переменной окружения сервера и возвращайте нормализованный JSON. LangChain или LangGraph выбирайте позже по сложности процесса.

Диагностика

Если что-то не работает

404 · n8n Test / Production

Test webhook должен быть запущен в режиме ожидания. Production URL доступен только у активированного workflow. Проверьте часть /webhook-test/ или /webhook/.

Invalid JSON

Убедитесь, что ответ — корректный JSON, Content-Type равен application/json, а строки заключены в двойные кавычки.

Пустой ответ

Верните непустое поле message, text или output. Проверьте выражение в узле Respond to Webhook.

CORS

Браузер блокирует прямой запрос, если сервер не разрешил origin страницы. Настройте CORS у провайдера или используйте Python backend.

401 · API key

Проверьте ключ и заголовок Authorization: Bearer …. Никогда не добавляйте ключ в URL.

429 · Rate / concurrency

Тариф допускает 30 запросов в минуту и 3 одновременных потока. Подождите завершения запросов и повторите позже.

Timeout

Запрос выполнялся слишком долго. Проверьте логи выбранного маршрута и попробуйте более короткий запрос.

Безопасность прежде всего

Не помещайте API-ключ в URL, сообщения или скриншоты. В прямом режиме ключ доступен браузеру; для команды и production используйте backend. По вашему тарифу NeuralDeep хранит историю логов 30 дней.
