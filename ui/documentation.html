ИИ Агенты: обучение и эксперименты в браузере

AI Агенты — это помощники на основе языковых моделей, которые используют инструкции, контекст диалога и внешние инструменты для решения задач. В AI Agents Lab можно изучать поведение AI Агентов: менять настройки модели, смотреть полный запрос и ответ сервера, подключать функции и проверять результаты их вызова.

Лаборатория ИИ Агентов объединяет чат с моделями, лабораторные работы и библиотеку Tools / function calling.

Подключение к LLM

Пройдите шаги по порядку: получите личный ключ, настройте NeuralDeep LLM Provider и отправьте первое сообщение. Ссылки со стрелкой на настройки открывают панель рядом с Помощью независимо от режима окон; указанное поле плавно подсвечивается два раза.

NeuralDeep: регистрация и получение API-ключа
  1. Откройте NeuralDeep, затем личный кабинет. Зарегистрируйтесь или войдите; проверьте, что у аккаунта есть доступ к API и выбранной модели. NeuralDeep · Личный кабинет
  2. В личном кабинете найдите раздел API-ключей, создайте ключ и скопируйте его. В каталоге моделей скопируйте точное API-имя модели, доступной вашему аккаунту: название тарифа и имя модели могут различаться.

AI Agents Lab: Настройки API
  1. Откройте настройки OpenAI API →. При первом посещении примите соглашение. В списке провайдеров будет выбран NeuralDeep LLM Provider. Этот профиль уже создан — добавлять новый не нужно.
  2. В поле Base URL → укажите адрес https://api.neuraldeep.ru/v1. Не добавляйте /chat/completions: приложение добавляет путь самостоятельно.
  3. В поле API key → вставьте личный API-ключ из кабинета NeuralDeep без кавычек и без слова Bearer. Ключ скрыт; кнопка глаза позволяет проверить ввод.
  4. В поле «Модель» → укажите точное API-имя выбранной модели. В профиле указан пример qwen3.6-35b-a3b; замените его, если эта модель недоступна вашему аккаунту.
  5. Нажмите Tab или щёлкните вне поля: настройки сохраняются автоматически в этом браузере. Для пробного запроса оставьте остальные параметры профиля без изменений.
  6. Перейдите в чат к полю сообщения →. Убедитесь, что выбран режим OpenAI API. Введите «Ответь одним словом: привет» и нажмите кнопку отправки или Enter. Дождитесь ответа модели в чате — это подтверждает, что подключение работает.

Если ответа нет: при ошибке 401 проверьте ключ, при 403 — доступ аккаунта, при ошибке модели — её API-имя, при 429 — лимиты. При сетевой ошибке проверьте Base URL и разрешение браузерных запросов у провайдера. Сообщение об ошибке появится в чате.

Режимы работы

Режим определяет, куда отправляется сообщение. Выберите его в списке рядом с названием «Чат»; шестерёнка открывает настройки выбранного режима.

  • OpenAI API — запрос к языковой модели через совместимый API. Нужны профиль, URL, ключ и модель.
  • Webhook — запрос к вашему workflow, например в n8n. Нужен адрес обработчика; модель и инструменты настраиваются в workflow.
  • Stub — учебный ответ из локального JSON-файла. Подходит для знакомства с интерфейсом без вызова LLM.
Что меняется при выборе режима

Меняются параметры подключения и источник ответа. Поле сообщения остаётся тем же. Режим подключения и раскладка окон — отдельные настройки: один выбирает обработчик, другая — место открытия страницы.

Как работать с сайтом

Начните с чата и настроек подключения. Остальные страницы помогают выполнять задания и подключать инструменты. Ниже — назначение элементов интерфейса.

Хедер: страницы и управление
  • Меню — дополнительные настройки приложения и ссылки.
  • Помощь — этот справочник. Лабы — задания и отчёты. Tools — библиотека HTTP-инструментов. MCP — библиотека MCP-серверов и их инструментов. Чат — сообщения и ответы.
  • Список режимов — Webhook, OpenAI API или Stub. Шестерёнка — настройки выбранного режима; повторное нажатие не закрывает панель.
  • Индикатор подключения — адрес или профиль и состояние последнего запроса; проверьте его перед отправкой.
  • Прямоугольник раскладки — место открытия следующей страницы. Жук — дебаг скрыт, только полоска или раскрыт.
  • Корзина — очистить чат. RU/EN — язык интерфейса. Солнце/луна — тема.
Чат: сообщение, ответ и инструменты
  • Поле сообщения — введите запрос. Enter отправляет, Shift+Enter добавляет строку. Стрелка отправки выполняет запрос.
  • Подсказки — готовые варианты запросов; выберите и проверьте текст перед отправкой.
  • Ответ — результат выбранного режима. Копирование сохраняет текст в буфер; Debug показывает запрос, ответ и служебные данные.
  • Tool Call — просьба модели выполнить инструмент. Проверьте имя и аргументы, выполните доступный HTTP-вызов или введите результат вручную, затем продолжите с tool results.
  • Ручной/автоматический режим инструментов — управление продолжением цепочки. «Пауза» останавливает автоматическое продолжение, «Следующий шаг» запускает очередной шаг, когда эти кнопки доступны.
Настройки: Webhook, OpenAI API и Stub
  • Webhook: GET/POST — метод; TEST/PROD — выбранный URL; поле адреса — обработчик; список недавних подключений — сохранённые адреса; «Проверить URL» — проверка. Нажатие на ID копирует его, «Начать новую сессию» создаёт новый ID разговора.
  • OpenAI API: список профилей выбирает подключение; «+» создаёт профиль, Clone копирует, карандаш меняет имя, удаление доступно для личных профилей. Защищённый профиль преподавателя меняйте через копию.
  • Base URL, API key, Модель — адрес, ключ и API-имя модели. Системный промпт задаёт инструкции. Параметры генерации меняйте по одному; «?» рядом с полем объясняет его действие.
  • История сообщений включает предыдущие реплики в запрос. Tools включает определения функций; JSON Schema задаёт аргументы, HTTP-настройки описывают выполнение.
  • Предпросмотр показывает endpoint, заголовки и тело будущего запроса; кнопки копируют JSON и cURL. Это просмотр, а не редактор истории.
  • Stub: выберите файл ответа и задержку, настройте показ Debug и подсказок. Результат берётся из файла, а не генерируется моделью.
Лабы: задания и отчёт

Выберите работу в верхней полосе. Содержание ведёт к цели, подготовке, экспериментам и отчёту. Раскройте ответ задания, заполните результат и выводы: прогресс обновится автоматически. Автор и группа попадут в экспорт. «Скачать отчёт» предлагает форматы; «Загрузить JSON» подключает работу или восстанавливает отчёт. Ответы сохраняются в текущем браузере.

Tools и MCP: библиотеки

Выберите готовый пример или создайте своё определение. У Tools задайте схему аргументов, HTTP-запрос и соответствие полей; проверьте результат перед использованием. У MCP настройте подключение к серверу и доступные инструменты. Импорт и экспорт JSON переносят определения. Доступность вызова зависит от подключения и выбранного инструмента.

Панели и окна

Панели позволяют держать рядом, например, лабораторную и чат. Выбранная раскладка действует при следующем открытии страницы; переключение раскладки само по себе ничего не закрывает.

  • Новая панель СПРАВА — новая страница открывается справа.
  • Новая панель на весь экран — выбранная страница занимает рабочую область приложения.
  • Новая панель СЛЕВА — новая страница открывается слева.
Переключение раскладки

Одинаковая иконка в хедере сайта и заголовке каждой панели управляет одной настройкой. Цикл: справа → весь экран → слева → весь экран → справа. Подсказка сообщает выбранный режим. На узком экране панели располагаются сверху и снизу.

Кнопки заголовка панели
  • Иконки страниц и шестерёнка — открыть страницу или настройки. При двух панелях кнопки заголовка выбирают содержимое этой панели.
  • Две стрелки — поменять панели местами.
  • Прямоугольник — режим следующего открытия, синхронизирован с хедером.
  • Четыре уголка — развернуть текущую панель на рабочую область. Выбранный режим открытия не меняется.
  • Крестик — закрыть эту панель, оставив соседнюю. Последнюю панель закрыть нельзя.
Размер, сохранение состояния и ссылки из помощи

Перетаскивайте разделитель, чтобы изменить размеры; с клавиатуры используйте стрелки после фокуса на разделителе. Переключение страниц сохраняет состояние уже открытых панелей. Перезагрузка — отдельное действие: не рассчитывайте на сохранение текста чата.

Три ссылки в начале этой помощи открывают чат, лабы или Tools рядом с помощью независимо от режима. Помощь остаётся видимой, а настройка раскладки не меняется. Это позволяет посмотреть интерфейс и вернуться к инструкции.

Практика с моделью

OpenAI API — одно из направлений практики: параметры генерации, системные инструкции, история сообщений и JSON Schema. Для автоматизации используйте Webhook.

В библиотеке Tools приложение выполняет HTTP-запрос и передаёт результат обратно модели. Модель выбирает функцию и формирует аргументы; сами данные получает приложение.

Первый запрос к LLM

Начните с пошагового подключения к LLM: там есть ссылки на каждый нужный параметр.

  1. Откройте настройки NeuralDeep LLM Provider →, проверьте URL, личный ключ и модель.
  2. Откройте поле сообщения в чате →, введите «Ответь одним словом: привет» и нажмите Enter.
  3. Дождитесь ответа. Для изучения запроса включите Debug кнопкой жука; найдите choices[0].message.content в полном ответе.
Если преподаватель выдал код доступа

Откройте сайт по ссылке преподавателя с параметром ?provider_access=ваш-код в адресе. Затем откройте настройки →. Скрытый Default LLM Provider станет доступен в этой вкладке. Его URL и ключ не отображаются; личный ключ для него не нужен. Для личного подключения используйте NeuralDeep LLM Provider.

OpenAI API · Chat Completions

Как устроен запрос к моделиHow a model request works

API — интерфейс, через который приложение обращается к модели. Этот чат отправляет JSON на POST /chat/completions: model выбирает модель, а messages[] содержит инструкции и реплики. OpenAI-совместимый сервер использует похожий формат, но набор поддерживаемых параметров может отличаться.

temperature и top_p регулируют выбор следующего токена; меняйте один из них за раз. max_completion_tokens ограничивает ответ, n запрашивает варианты. Доступные значения и ограничения зависят от модели; кнопки «?» у полей показывают справку и границы этой формы.

tools описывает функции. Модель возвращает имя и аргументы; приложение выполняет действие или вы вводите результат вручную. Затем результат отправляется модели для продолжения. Сворачивание карточки скрывает только редактор и не удаляет функцию из запроса.

Перед отправкой проверьте предпросмотр JSON. После ответа сравните choices, finish_reason и usage в полном ответе провайдера.

The API lets an app communicate with a model. This chat posts JSON to /chat/completions: model selects the model and messages[] carries instructions and conversation turns. Compatible providers can support different subsets of parameters.

temperature and top_p affect token selection; adjust one at a time. max_completion_tokens limits output and n requests alternatives. The question marks beside fields explain the form limits and effects.

tools defines functions. The model requests a function and arguments; the app executes it or you enter its result, then send that result back for continuation. Collapsing a function hides its editor without removing it from the request.

Inspect the JSON preview before sending, then compare choices, finish_reason and usage in the provider response.

Как проходит запрос

Выбор режима определяет маршрут сообщения.

HTTP · JSON

Что именно отправляет текущий UI

message — ваш текст. sessionId — метка разговора: по ней workflow понимает, какие сообщения относятся к одному диалогу.

POST · Content-Type: application/json
{ "message": "Привет!", "sessionId": "session_abc123" }
GET · QUERY PARAMETERS
?sessionId=session_abc123&message=Привет%21

Какой ответ принимает чат

RECOMMENDED SUCCESS
{
  "message": "Готово!",
  "suggestions": ["Дальше"],
  "debug": { "node": "Agent" }
}

Вместо message допустимы алиасы text или output. suggestions и debug необязательны.

ERROR
{ "error": "Не удалось вызвать модель" }

Любой непустой JSON чат может показать как есть, но единый формат с message проще поддерживать.

Настройка Webhook

Webhook соединяет чат с обработчиком: тот получает сообщение, выполняет вашу логику и возвращает ответ.

В n8n создайте Webhook → обработку message/sessionId → Respond to Webhook с непустым message. Вставьте URL в настройки Webhook. Test работает при ожидании тестового события, Production — у активированного workflow.

Диагностика

Если что-то не работает

Сначала проверьте выбранный режим и настройки подключения, затем найдите статус или сообщение об ошибке в Debug. Ниже — пояснения частых ошибок.

404 · n8n Test / Production

Test webhook должен быть запущен в режиме ожидания. Production URL доступен только у активированного workflow. Проверьте часть /webhook-test/ или /webhook/.

Invalid JSON

Убедитесь, что ответ — корректный JSON, Content-Type равен application/json, а строки заключены в двойные кавычки.

Пустой ответ

Верните непустое поле message, text или output. Проверьте выражение в узле Respond to Webhook.

CORS

Браузер блокирует прямой запрос, если сервер не разрешил origin страницы. Настройте CORS у провайдера или используйте Python backend.

401 · API key

Проверьте ключ и заголовок Authorization: Bearer …. Никогда не добавляйте ключ в URL.

429 · Rate / concurrency

Тариф допускает 30 запросов в минуту и 3 одновременных потока. Подождите завершения запросов и повторите позже.

Timeout

Запрос выполнялся слишком долго. Проверьте логи выбранного маршрута и попробуйте более короткий запрос.

Безопасность прежде всего

Не помещайте API-ключ в URL, сообщения или скриншоты. В прямом режиме ключ доступен браузеру; для команды и production используйте backend. По вашему тарифу NeuralDeep хранит историю логов 30 дней.
