Как устроен OpenAI API и что меняют параметры →

12 экспериментов, один принцип: меняйте только один независимый параметр за раз. Задания 1–7 и 12 выполняются в чате; для 8–11 нужен API-клиент преподавателя — этих полей пока нет в форме сайта.

Перед первым запросом

Подготовьте рабочее место

  1. Перейдите в чат по ссылке в хедере и примите соглашение. Выберите OpenAI API в хедере, затем нажмите значок инструментов для открытия настроек режима.
  2. Выберите настроенный преподавателем профиль и нажмите Clone, чтобы проводить опыты в копии. Используйте предоставленные URL и модель.
  3. Очистите «Системный промпт», выключите «Отправлять предыдущие сообщения в OpenAI API» и Tools / function calling. Очистите чат.
  4. Задайте параметры ниже. Включите режим «Дебаг раскрыт» кнопкой жука в хедере или в настройках.
Контрольные настройки
temperature: 0.7 · top_p: 1 · n: 1 · max_completion_tokens: 512

Перед отправкой введите текст и проверьте «Предпросмотр запроса» → «Тело JSON». После отправки раскройте Debug → «Запрос» / «Полный ответ». Сохраняйте фактические JSON каждой попытки.

Поля choices и usage ищите в полном ответе провайдера. Время выполнения и другие служебные данные UI — отдельные измерения интерфейса. Предпросмотр показывает запрос, но не является JSON-редактором.

Между заданиями возвращайтесь к контрольным настройкам. В опытах со случайной генерацией сделайте по 3 повторения для каждого значения. Если провайдер отклонил параметр или не вернул поле, запишите это в отчёт; отсутствие ошибки само по себе не доказывает поддержку.

От текста к инструментам

12 последовательных экспериментов

Для каждого: контрольный запуск → изменение → сравнение JSON → короткий вывод.

01

Первый запрос

Отправьте текст с контрольными настройками. Затем измените только просьбу: вместо «одним предложением» напишите «тремя предложениями».

ПРОМПТ
Объясни REST API одним предложением.

Проверьте messages[0].role: "user" и текст запроса; сравните choices[0].message.content и usage.prompt_tokens / completion_tokens / total_tokens.

Что изменилось в ответе и расходе токенов после изменения инструкции?

02

Выбор модели

Повторите промпт «Объясни REST API одним предложением.» на текущей модели, затем измените только поле «Модель» на вторую, доступную по вашему подключению. Если преподаватель предоставил только одну модель, отметьте задание как недоступное.

Сравните model, choices[0].message.content, usage и время UI. Имя в ответе фиксируйте ровно так, как его вернул провайдер.

Какие различия повторяются, а какие могут быть случайными?

03

Контекст — это сообщения

  1. Очистите чат. При выключенном контексте отправьте «Меня зовут Алексей.», затем «Как меня зовут?».
  2. Очистите чат ещё раз. Включите отправку предыдущих сообщений и повторите те же две реплики.
  3. Сравните запросы ко второй реплике. После опыта выключите контекст.

При включённом контексте в messages[] должны появиться предыдущие user и assistant. Сравните ответ и usage.prompt_tokens. Непустой системный промпт UI добавляет с ролью system.

За счёт каких данных модель смогла восстановить имя?

04

Случайность · temperature

Сравните temperature: 0.2 и 1.2: по 3 запуска при top_p: 1 и выключенном контексте.

ПРОМПТ
Придумай название стартапа, который использует AI для обучения программистов.

Считайте уникальные названия в choices[0].message.content. Проверяйте значение температуры в запросе: отдельного поля температуры в ответе может не быть.

При каком значении ответы разнообразнее? Достаточно ли трёх попыток для уверенного вывода?

05

Выбор токенов · top_p

С тем же промптом про название стартапа сравните top_p: 0.2 и 1, по 3 запуска. Зафиксируйте temperature: 0.7 для обеих серий.

Сравните уникальные варианты и формулировки в choices[0].message.content; убедитесь по запросам, что температура не менялась.

Как ограничение выборки повлияло на разнообразие?

06

Ограничение длины

В поле «Максимум completion-токенов» сравните 32 и 256.

ПРОМПТ
Подробно расскажи историю языка Python.

Смотрите choices[0].finish_reason, usage.completion_tokens и обрыв текста. length указывает на достижение лимита, stop — на обычное завершение. У reasoning-модели часть лимита может уйти на внутреннее рассуждение.

Почему лимит токенов не равен числу слов и не гарантирует завершённый ответ?

07

Несколько вариантов · n

С промптом про название стартапа сравните «Варианты ответа · n»: 1 и 3. Остальные параметры оставьте контрольными.

В полном ответе посчитайте элементы choices[], проверьте их index, тексты и usage. Видимый ответ чата не заменяет проверку всего массива. Если сервер вернул один вариант или ошибку, зафиксируйте фактическое поведение.

Сколько вариантов действительно получено и как изменилось число completion-токенов?

08

Повторяемость · penalties

Расширение · API-клиент преподавателя

В форме сайта этих параметров нет. В отдельном клиенте сравните frequency_penalty: 0 → 2 при presence_penalty: 0.

ПРОМПТ
Напиши длинный рекламный текст про кофе, много раз используя слова кофе, вкусный и ароматный.

Затем проведите отдельную серию: presence_penalty: 0 → 2, frequency_penalty: 0, промпт: «Рассказывай о разработке программного обеспечения в свободной форме.»

По 3 повтора на значение. В message.content сравните повторы слов относительно длины текста; во второй серии — разнообразие тем. Поддержка зависит от модели и провайдера.

Отличается ли влияние штрафа за частоту от штрафа за само появление токена?

09

Вероятности токенов

Расширение · API-клиент преподавателя

Этих полей нет в форме сайта. В отдельном клиенте отправьте «Продолжи одним словом: Небо сегодня». Сравните logprobs: false → true, не добавляя top_logprobs. Затем при logprobs: true отдельно сравните top_logprobs: 1 → 3, если модель поддерживает эти значения.

Ищите choices[0].logprobs.content[]: token, logprob, top_logprobs. Не принимайте логарифм вероятности за процент.

Какие альтернативы были у одного токена? Почему это не оценка достоверности всего ответа?

10

Структурированный ответ

Расширение · API-клиент преподавателя

response_format нельзя задать в форме сайта. В отдельном клиенте отправьте «Верни JSON с полями city и country для города Париж». Сравните запрос без response_format и запрос с фрагментом ниже, если модель поддерживает JSON Schema.

Фрагмент запроса: response_format
ДОБАВИТЬ В ТЕЛО ЗАПРОСА
"response_format": {
  "type": "json_schema",
  "json_schema": {
    "name": "city_info",
    "strict": true,
    "schema": {
      "type": "object",
      "properties": {
        "city": { "type": "string" },
        "country": { "type": "string" }
      },
      "required": ["city", "country"],
      "additionalProperties": false
    }
  }
}

Разберите choices[0].message.content как JSON; проверьте обязательные поля, типы и отсутствие лишних полей. Учтите finish_reason и возможный отказ. Просьба «верни JSON» в промпте сама по себе не включает response_format.

Чем синтаксически корректный JSON отличается от соответствия заданной схеме?

11

Reasoning и подробность

Расширение · API-клиент преподавателя

Этих настроек нет в форме сайта. Для поддерживающей их модели в клиенте преподавателя сравните reasoning_effort: low → high, сохраняя одинаковый достаточный лимит токенов и остальные параметры.

ПРОМПТ
Три станка делают три детали за три минуты. За сколько минут шесть таких станков сделают двенадцать деталей? Дай ответ и краткое объяснение.

Отдельно сравните verbosity: low → high при фиксированном reasoning_effort. Используйте только значения, разрешённые для выбранной модели.

Смотрите usage.completion_tokens_details.reasoning_tokens, usage.completion_tokens, длину и правильность ответа (проверка: 6 минут). Отсутствующее поле не считайте нулём.

Стали ли ответы точнее или только длиннее? Что удалось измерить?

12

Function calling · полный цикл

  1. Вернитесь в чат к контрольным настройкам. Включите Tools / function calling. Удалите лишние определения из копии профиля, нажмите «+ Добавить функцию».
  2. Имя: get_weather. Описание: «Получить учебные данные о погоде в городе». Вставьте схему ниже в «Параметры · JSON Schema». Выключите «Параллельные tool calls»; HTTP-настройку оставьте пустой — результат введём вручную.
  3. При «Выбор tool» = none отправьте «Какая сейчас погода в Москве? Используй get_weather.» Затем повторите тот же промпт с required. Меняется только tool_choice.
  4. Для полного цикла очистите чат, выберите auto и заново отправьте тот же промпт. Режим required сохраняется в продолжении и может потребовать ещё один вызов вместо текстового ответа.
  5. Когда появится tool call, проверьте имя и аргументы. В поле «Результат» введите {"city":"Москва","temperature_c":18,"condition":"облачно","source":"учебный пример"}. Это вымышленные данные для опыта.
  6. Нажмите «Продолжить с tool results». Проверьте следующий запрос и итоговый ответ модели.
Схема аргументов get_weather
ПАРАМЕТРЫ · JSON SCHEMA
{
  "type": "object",
  "properties": {
    "city": { "type": "string", "description": "Название города" }
  },
  "required": ["city"],
  "additionalProperties": false
}

В ответе: choices[0].message.tool_calls[], function.name, JSON-строка function.arguments, finish_reason. В продолжении: сообщение assistant с вызовом и сообщение tool с соответствующим tool_call_id. Если вызова нет, запишите результат провайдера.
